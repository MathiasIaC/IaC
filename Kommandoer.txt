Terraform kommandoer:

Terraform init - initialiserer terraform i mappen hvor main.tf er - kjør først

Terraform fmt - formaterer filene i god struktur

Terraform validate - Sjekker om konfigurasjon er valid og klar til deploy

Terraform plan - viser hva som skal skje, evt feil dukker opp
 - Kan legge til plan -out="plan-navn" for å lage en plan med navn

Terraform apply - Deployer planen og endringene
 - Kan legge til "plan-navn" hvis brukt dette for å utføre den planen

Terraform destroy - Fjern deployen etter testing
 - for å destroye prod/dev "terraform destroy -var-file="terraform.tfvars.dev"

Endringer og videre utvikling av kode:
git branch
git checkout -b feature/terraform-(...)
- gjør endringer og commit
- create pull request og følg instrukser i github
- delete branch på github og lokalt: git checkout -b feature/terraform-(...)
- git fetch --prune

Når en ny versjon av main er oppe å kjører:
git tag -a oblig2-v(2.0.0) -m "Oblig2 Release v(2.0.0)>> features: (-Add tag to RG)
>> Deployment status: (OK)
>> Verfied all environments: (OK)"

git push origin oblig2-v(2.0.0)
Gå inn på github og draft new relaease

Sjekke alle tags/verjsoner:
- git tag -l "oblig2-*" --sort=creatordate

Sjekke forskjeller mellom versjoner:
- git log oblig2-v(2.0.0)..oblig2-v(2.1.0) --oneline
- git show (id)
- git show oblig2-v(2.0.0) / viser tag melding
- Skriv "q" hvis man vil ut 

Rollback til en annen versjon:
- Lag ny branch: git checkout -b hotfix/rollback-to-v(2.0.0)
- git checkout oblig2-v(2.0.0) --(terraform)
- git status eller git diff --staged / ser hva som er endret 
- git commit -m "Rollback to v2.0.0 configuration"
- git push origin hotfix/rollback-to-v(2.0.0)
- samme gjennomgang ved vanlig push av ny kode
- git checkout main
- git pull origin main
- Legg til ny tag for rollbacken og draft denne som release
